# PROMPT — REFONTE COMPLÈTE DE LA SECTION « FRAIS » DE L’ADMIN PANEL BIZ-TRANSPAY

Je veux modifier **la structure de l’Admin Panel**, principalement la section **Frais**, tout en conservant certaines rubriques existantes. Fais cette modification proprement et sans casser les fonctionnalités déjà opérationnelles.

## 1. MENU « FRAIS »

Lorsque l’administrateur ouvre **Frais**, conserver uniquement ces trois catégories :

* **Dépôt**
* **Retrait**
* **Conversion**

Pour le moment, la catégorie **Conversion reste visible**, mais elle sera supprimée dans une prochaine étape si nécessaire. **Ne modifie pas encore les autres éléments de cette catégorie sans nouvelle instruction.**

---

# 2. SECTION « DÉPÔT » — SUPPRESSION DE L’ANCIEN SYSTÈME

Dans **Dépôt**, supprimer complètement l’ancien système de configuration manuelle intitulé **« Dépôt Mobile Money »**.

L’ancien fonctionnement permettant à l’administrateur :

* d’ajouter manuellement un pays ;
* d’ajouter manuellement un opérateur ;
* de créer manuellement les capacités de paiement ;

doit être supprimé.

### Nouvelle règle fondamentale

Les **pays et opérateurs disponibles pour le dépôt ne doivent plus être créés manuellement par l’administrateur**.

Ils doivent provenir **directement de la passerelle/API de paiement actuellement intégrée au système**.

Le catalogue doit donc être alimenté automatiquement à partir des informations réellement disponibles et fonctionnelles dans l’API.

---

# 3. PAYS ÉLIGIBLES AU DÉPÔT

Lorsqu'un pays est disponible dans l’API de paiement, il doit automatiquement apparaître dans l’Admin Panel.

Exemple :

**Togo**

Si l’API indique que le Togo dispose de :

* TMoney ;
* MTN Mobile Money ;
* ou d’autres opérateurs réellement disponibles ;

ces opérateurs doivent être récupérés depuis l’API et affichés automatiquement.

⚠️ **Ne pas inventer d’opérateurs et ne pas afficher des opérateurs qui ne sont pas réellement retournés/supportés par l’API.**

---

# 4. STRUCTURE DU TABLEAU « DÉPÔT »

Le tableau de configuration doit présenter au minimum :

| Pays | Code | Opérateur | Devise | Frais passerelle | Frais plateforme | Total | Minimum | Maximum | Statut | Actions |
| ---- | ---- | --------- | ------ | ---------------: | ---------------: | ----: | ------: | ------: | ------ | ------- |

Les informations **Pays, Code, Opérateur et Devise** doivent provenir de la passerelle/API.

Les informations configurables par l'administrateur sont principalement :

### Frais passerelle

Frais appliqués par le prestataire.

### Frais plateforme

Frais supplémentaires définis par Biz-transPay.

### Total

Calcul automatique :

**Total = Frais passerelle + Frais plateforme**

Ne pas demander à l’administrateur de saisir manuellement le total.

---

# 5. MINIMUM ET MAXIMUM

L’administrateur doit pouvoir définir :

* **Montant minimum de dépôt**
* **Montant maximum de dépôt**

Ces limites doivent être appliquées côté utilisateur.

Exemple :

```text
Minimum : 500 XOF
Maximum : 1 000 000 XOF
```

Si l’utilisateur saisit un montant inférieur au minimum ou supérieur au maximum, afficher immédiatement un message clair.

---

# 6. FRAIS PLATEFORME ET FRAIS PASSERELLE

L’administrateur doit pouvoir modifier séparément :

### Frais passerelle

Le coût facturé par la passerelle.

### Frais plateforme

Le coût ajouté par Biz-transPay.

Ces deux valeurs doivent rester distinctes dans l’interface d’administration.

Le système calcule automatiquement le total.

Exemple :

```text
Frais passerelle : 2 %
Frais plateforme : 1 %
Total : 3 %
```

---

# 7. ACTIVATION / DÉSACTIVATION D’UN PAYS

Chaque pays doit avoir un bouton :

**Activé / Désactivé**

Si l’administrateur désactive un pays :

* le pays ne doit plus être proposé aux utilisateurs pour les dépôts ;
* aucun nouveau dépôt ne doit pouvoir être lancé avec ce pays ;
* les anciennes transactions ne doivent pas être supprimées ;
* les transactions historiques doivent rester accessibles.

Si l’administrateur réactive le pays :

* il redevient automatiquement disponible pour les utilisateurs.

---

# 8. ACTIVATION / DÉSACTIVATION D’UN OPÉRATEUR

La même logique doit être appliquée individuellement aux opérateurs.

Exemple :

```text
Togo
 ├── TMoney       ACTIVÉ
 ├── MTN          ACTIVÉ
 └── Orange       DÉSACTIVÉ
```

Si un opérateur rencontre un problème, l’administrateur peut le désactiver sans désactiver tout le pays.

---

# 9. MESSAGE CÔTÉ UTILISATEUR

Lorsqu’un opérateur est désactivé, il ne doit plus être sélectionnable.

Si nécessaire, afficher clairement :

> **Opérateur temporairement indisponible. Veuillez sélectionner un autre moyen de paiement.**

Pour un pays entièrement désactivé :

> **Ce moyen de paiement est temporairement indisponible. Veuillez réessayer plus tard ou sélectionner une autre méthode.**

Le message doit être professionnel et compréhensible.

---

# 10. SUPPRESSION D’UN PAYS

L’administrateur doit également disposer d’une possibilité de **supprimer un pays du catalogue local**.

⚠️ Mais attention :

La suppression ne doit pas supprimer le pays de l’API du prestataire.

Elle doit uniquement retirer/désactiver sa configuration dans Biz-transPay.

Lors d’une nouvelle synchronisation avec l’API, ne pas recréer automatiquement un pays supprimé si l’administrateur a explicitement choisi de le supprimer.

Prévoir donc une distinction logique entre :

* pays fourni par l’API ;
* pays activé dans Biz-transPay ;
* pays désactivé ;
* pays masqué/supprimé par l’administrateur.

---

# 11. SYNCHRONISATION AVEC L’API

Le système doit pouvoir récupérer automatiquement les capacités disponibles auprès de la passerelle.

La logique doit être :

```text
API passerelle
      ↓
Pays disponibles
      ↓
Opérateurs disponibles
      ↓
Devises disponibles
      ↓
Synchronisation Biz-transPay
      ↓
Catalogue Dépôt Admin
      ↓
Catalogue Dépôt Utilisateur
```

L’Admin Panel ne doit donc plus obliger l’administrateur à saisir manuellement tous les pays et opérateurs un par un.

---

# 12. IMPORTANT — NE PAS CONFONDRE API ET CONFIGURATION ADMIN

L’API est la **source des capacités de paiement**.

L’Admin Panel sert principalement à gérer :

* activation ;
* désactivation ;
* suppression/masquage ;
* frais passerelle ;
* frais plateforme ;
* minimum ;
* maximum.

L’administrateur ne doit pas avoir besoin de recréer manuellement les pays et opérateurs déjà fournis par l’API.

---

# 13. RETRAIT

Appliquer **la même philosophie à la partie Retrait**.

Les pays et opérateurs disponibles pour le retrait doivent également être basés sur les capacités réellement disponibles auprès de la passerelle/API.

L’administrateur doit pouvoir gérer :

* frais passerelle ;
* frais plateforme ;
* minimum ;
* maximum ;
* activation/désactivation du pays ;
* activation/désactivation de l’opérateur.

Mais il ne doit pas être obligé de recréer manuellement tout le catalogue fourni par la passerelle.

---

# 14. PARTIE « CONVERSION »

Pour cette étape, **ne pas développer de nouvelle fonctionnalité de conversion**.

La logique de conversion sera traitée séparément.

---

# 15. MODIFICATION DU MENU ADMINISTRATEUR

Dans le menu Admin Panel, supprimer complètement :

### ❌ Journal d’activité

Cette rubrique ne doit plus apparaître dans le menu.

---

# 16. CONSERVER LES RUBRIQUES SUIVANTES

Ne pas supprimer les rubriques suivantes :

### ✅ Administrateur

La conserver telle quelle pour le moment.

### ✅ Support et Chat

La conserver.

### ✅ Notifications

La conserver.

Je fournirai ultérieurement les nouvelles fonctionnalités ou modifications à appliquer à ces sections.

---

# 17. RÈGLE IMPORTANTE POUR CETTE ÉTAPE

**Ne touche pas aux fonctionnalités que je n’ai pas demandé de modifier.**

Ne modifie pas :

* les transactions existantes ;
* les soldes ;
* les wallets ;
* les utilisateurs ;
* les KYC ;
* les paiements déjà enregistrés ;
* les API existantes ;
* les webhooks ;
* les retraits fonctionnels ;
* les dépôts fonctionnels.

Cette étape concerne principalement **la restructuration du catalogue de frais et des capacités de dépôt/retrait dans l’Admin Panel**.

---

# 18. OBJECTIF FINAL

Je veux obtenir un système beaucoup plus automatique :

**La passerelle/API détermine les pays, opérateurs et devises réellement disponibles.**

**Biz-transPay permet ensuite à l’administrateur de contrôler leur disponibilité et leur tarification.**

Donc :

> **API = source des moyens de paiement disponibles.**
> **Admin Panel = gestion des frais, limites et activation/désactivation.**
> **Utilisateur = voit uniquement les moyens actuellement disponibles et activés.**

Avant de considérer cette modification comme terminée, vérifie que la synchronisation entre l’API, l’Admin Panel et l’interface utilisateur fonctionne correctement et qu’un pays ou opérateur désactivé côté administration devient immédiatement indisponible côté utilisateur.
