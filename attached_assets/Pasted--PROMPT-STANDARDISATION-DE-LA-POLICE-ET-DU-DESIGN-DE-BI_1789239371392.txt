# PROMPT — STANDARDISATION DE LA POLICE ET DU DESIGN DE BIZ-TRANSPAY

Je veux mettre en place une **identité visuelle unique et permanente** pour toute l’interface de Biz-transPay.

### 1. POLICE D’ÉCRITURE

À partir de maintenant, **cesse complètement d’utiliser Google Fonts ou toute autre police externe** pour l’interface.

Je vais te fournir **ma propre police d’écriture**.

Une fois que je t’aurai envoyé le fichier de police :

* intègre cette police directement dans le projet ;
* utilise-la comme **police principale de toute l’application** ;
* applique-la à tous les textes ;
* titres ;
* sous-titres ;
* boutons ;
* formulaires ;
* menus ;
* cartes ;
* tableaux ;
* notifications ;
* messages d’erreur ;
* pages de paiement ;
* dashboard ;
* paramètres ;
* interface administrateur ;
* documentation affichée dans l’application.

Si plusieurs variantes de ma police sont fournies (Regular, Medium, SemiBold, Bold, etc.), utilise chaque variante selon son usage approprié.

**Ne charge plus Google Fonts.**

La police doit être hébergée/localement intégrée au projet afin que l'application ne dépende pas d'un service externe pour l'affichage des textes.

---

# 2. DESIGN DE RÉFÉRENCE

Je vais également te fournir **un lien vers une plateforme de référence**.

Tu dois analyser cette plateforme afin de comprendre son système visuel :

* disposition des éléments ;
* positionnement des cartes ;
* tailles ;
* espacements ;
* marges ;
* bordures ;
* rayons des coins ;
* boutons ;
* champs de formulaire ;
* navigation ;
* hiérarchie visuelle ;
* densité de l'interface ;
* responsive design ;
* organisation générale des pages.

⚠️ **Je ne veux pas que tu copies le site.**

Utilise-le uniquement comme **référence esthétique et UX** pour établir le langage visuel de Biz-transPay.

---

# 3. CRÉER UN DESIGN SYSTEM UNIQUE

Après avoir analysé la plateforme de référence, crée un **Design System centralisé pour Biz-transPay**.

Il doit définir notamment :

### Typographie

* police principale ;
* tailles ;
* poids ;
* hauteur de ligne ;
* titres ;
* textes secondaires ;
* labels ;
* boutons.

### Cartes

* largeur ;
* hauteur ;
* padding ;
* radius ;
* ombres ;
* espacement entre les cartes.

### Boutons

* hauteur ;
* radius ;
* typographie ;
* icônes ;
* états normal/hover/disabled/loading.

### Formulaires

* champs ;
* labels ;
* placeholders ;
* bordures ;
* messages d'erreur ;
* états focus ;
* états disabled.

### Espacements

Définir une grille cohérente afin que toutes les pages utilisent les **mêmes espacements**.

---

# 4. IMPORTANT : NE PLUS CHANGER DE STYLE À CHAQUE MODIFICATION

Une fois ce Design System établi, **toutes les futures modifications de Biz-transPay doivent respecter exactement ce même système**.

Je ne veux plus que chaque nouvelle fonctionnalité apporte :

* une nouvelle police ;
* un nouveau style de carte ;
* un nouveau bouton ;
* un nouveau radius ;
* une nouvelle façon d'espacer les éléments ;
* un design différent des pages précédentes.

Toutes les nouvelles fonctionnalités doivent **réutiliser les composants et styles existants**.

---

# 5. COMPOSANTS RÉUTILISABLES

Lorsque c'est pertinent, crée des composants réutilisables pour :

* Card ;
* Button ;
* Input ;
* Select ;
* Modal ;
* Alert ;
* Badge ;
* Table ;
* Navigation ;
* Header ;
* Footer ;
* Wallet Card ;
* Transaction Card ;
* Payment Form.

Ainsi, lorsqu'une modification est nécessaire plus tard, nous pouvons modifier le composant central et conserver automatiquement une apparence cohérente dans toute l'application.

---

# 6. RESPONSIVE DESIGN

Le design de référence doit être adapté correctement à :

📱 Mobile
💻 Desktop
📲 Tablette

Il ne faut pas simplement réduire les éléments.

Il faut conserver une bonne hiérarchie visuelle et faire en sorte que les informations restent lisibles et correctement positionnées sur chaque écran.

---

# 7. AVANT DE MODIFIER LE CODE

Avant toute modification :

1. Analyse le design actuel de Biz-transPay.
2. Analyse la plateforme de référence que je vais fournir.
3. Identifie les différences.
4. Définis les règles du nouveau Design System.
5. Intègre ma police.
6. Vérifie les composants existants.
7. Réutilise les composants lorsqu'ils existent déjà.
8. Ne modifie pas les fonctionnalités métier qui fonctionnent.

**Le changement demandé concerne principalement l'identité visuelle et la cohérence du design.**

---

# 8. RÈGLE POUR LES PROCHAINES ÉTAPES

À partir de maintenant, considère :

**Ma police + le Design System défini à partir de la plateforme de référence = identité visuelle officielle de Biz-transPay.**

Pour chaque prochaine modification que je demanderai :

> **Conserve obligatoirement la même police, les mêmes règles de design, les mêmes composants, les mêmes espacements et la même logique visuelle, sauf si je demande explicitement de les modifier.**

Ne réintroduis jamais Google Fonts ou une autre police externe sans mon autorisation explicite.

**Objectif : Biz-transPay doit avoir une interface cohérente, professionnelle et reconnaissable sur toutes ses pages, aujourd'hui comme lors des prochaines évolutions du projet.**
